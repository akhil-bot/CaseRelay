3

Surviving the gap between sessions

A child's deadline is 17 days out; no chat session lives that long, so the case has to sleep in storage

Session-scoped agent

Nothing re-enters the case

  • Context dies with the run — day 17 arrives with no agent watching.
  • Replaying the whole history to catch up burns tokens and invites drift.
  • A stalled partner is indistinguishable from a partner nobody asked.
  • The volunteer becomes the only memory the system has.
Durable checkpoint

The case waits in Firestore, not in a session

  • State is an explicit document, so a restart loses nothing.
  • A due date, not a conversation, decides when work resumes.
  • The resume writes audit events under its own scheduler identity.
  • Human approval can sit pending indefinitely without blocking anything.

Why simulate

The interesting failures are partner failures. Simulation makes them reproducible in a test rather than rare in production.
reproducible
Least privilege in code, not in prompts

The education agent receives three fields out of fourteen because a function removed the rest, not because an instruction asked it not to look.

Authority is always human

Agents propose grants and open escalations; only a supervisor turns a proposal into a permission or clears a quarantine.

Deterministic where it must be

Projection and screening are plain rules, so the same payload always produces the same verdict and any refusal can be replayed.

Built for elapsed time

A case sleeps as a document with a due date, so a 17-day deadline survives restarts, redeploys and closed browser tabs.
